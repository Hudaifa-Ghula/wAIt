## What makes a strong entry

The challenge rewards **the problems solved and the useful functionality added**. A small, well-tested fix can be more valuable than a large feature.

- **Real impact:** explain who benefits and what becomes easier or more reliable.
- **Correctness:** demonstrate the change working and cover relevant edge cases.
- **Useful functionality:** add something people can use, with a clear path through the UI or setup.
- **Maintainability:** keep the change understandable, focused, and practical to support.

Examples include better task-state reliability, clearer onboarding, accessible controls, improved learning tools, and stronger integration tests. Larger integration or platform changes should start with an issue so the approach can be discussed.

## How selection will work

The creator may judge the entries directly or organize a community vote, depending on the submissions received. The chosen method will be announced **before judging or voting begins**.

If voting is used, publish the shortlist, voting window, eligibility to vote, and tie-handling before voting opens. The same published criteria should apply to every shortlisted entry. GitHub reactions or raw PR volume are not automatically votes.

## Submitting a PR

Follow [CONTRIBUTING.md](../CONTRIBUTING.md).

Submit your PR by the deadline. It does **not** need to be merged to qualify or win. Competition selection and merging are separate decisions; submitting or winning does not require the maintainer to accept the change into the project.

Each entry should include:

1. The problem or use case and the resulting improvement.
2. Reproduction steps, a demo, or screenshots where helpful.
3. Tests run and any limitations, including what was checked live versus simulated.
4. An explanation of any new permissions, stored data, external services, or dependencies.

AI-assisted contributions are welcome. You remain responsible for understanding, validating, and having the right to contribute the work. Keep private code and credentials out of PRs and demos. Report security vulnerabilities privately using [SECURITY.md](../SECURITY.md).
